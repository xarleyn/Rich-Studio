Markdown для Telegram с предпросмотром

Пишите текст во вкладке Markdown и проверяйте оформление рядом. RichPost работает с Rich Markdown для rich сообщений Telegram: в нём есть заголовки и таблицы, а правила отличаются от обычного MarkdownV2.

Начните с небольшого примера

В одном анонсе можно проверить заголовок, выделение времени, цитату, список и ссылку. Скопируйте текст в новый черновик, затем замените тему, время и адрес своими данными.

# Встречаемся в субботу

**Начало в 10:00.** Возьмите блокнот.

> Хорошие идеи начинаются с разговора.

- Обсудим планы
- Ответим на вопросы

[Подробности](https://example.com/meeting)

Предпросмотр должен показать отдельный заголовок, жирное время, цитату и два пункта списка. Адрес example.com здесь учебный: перед публикацией поставьте настоящую ссылку и проверьте, куда она ведёт.

Rich Markdown и MarkdownV2

Название Markdown объединяет несколько форматов. Инструкции для обычного Bot API с parse_mode=MarkdownV2 нельзя переносить сюда без проверки. Rich сообщения поддерживают другую структуру содержимого, в том числе заголовки, списки и таблицы. Вставка исходного текста в обычный чат также не заменяет отправку rich поста через редактор.

Для начала используйте небольшой понятный набор конструкций. Проверяйте новую конструкцию отдельно, а затем добавляйте её в большой пост. Это помогает быстрее найти причину, если ожидаемое выделение или перенос не появился.

Порядок работы в редакторе

  1. Создайте черновик и откройте Markdown. Вставьте пример или добавьте конструкцию из панели сниппетов.
  2. Проверяйте результат справа. На узком экране откройте вкладку «Предпросмотр», чтобы увидеть весь пост.
  3. Сохраните черновик, запустите бота и используйте «Мне в личку» для проверки в Telegram. Такой предпросмотр не публикует пост в выбранный канал.
  4. Если результат отличается, откройте «Как разобрал Telegram» и сравните полученную структуру. Исправьте исходный текст и повторите проверку.
  5. Выберите канал, проверьте ссылки и кнопки, затем публикуйте сразу или назначьте время.

Разберитесь с переносами и выделением

Абзац и отдельная строка

Один перенос внутри абзаца становится пробелом. Для нового абзаца оставьте пустую строку. Для переноса внутри того же абзаца используйте два пробела в конце строки или обратную косую черту. Если текст выглядит слишком плотным, сначала проверьте пустые строки, а не добавляйте случайные теги.

Жирный текст и подчёркивание

Двойные звёздочки выделяют текст жирным. Двойные подчёркивания тоже означают жирное выделение, а не линию под текстом. Для подчёркивания используйте разрешённый HTML тег <u>…</u> и проверьте результат. Не вставляйте в пост скрипты или оформление целой веб страницы.

Переключение между форматами

При переходе между визуальным режимом, HTML и Markdown редактор пытается преобразовать содержимое поста. Если конструкцию нельзя перенести без потери данных, переключение отменяется, а исходное содержимое сохраняется. Прочитайте сообщение редактора и продолжайте работу в исходном формате либо упростите проблемную часть.

JSON применяется отдельным действием. Неприменённые изменения исходника не следует считать опубликованной версией. Перед отправкой проверьте активный формат, сам предпросмотр и сохранённый черновик.

Проверка перед публикацией

Прочитайте пост без исходной разметки: понятны ли заголовки, не слиплись ли пункты списка, видно ли главное действие? Проверьте настоящие адреса ссылок и названия каналов. Локальный предпросмотр полезен для редактирования, но окончательный вид зависит от разбора и клиента Telegram.

Для строк и колонок используйте пример таблицы. Готовый текст можно поставить в очередь или передать работу с черновиком ИИ агенту через MCP.

Частые вопросы

Подойдут ли правила обычного MarkdownV2?

Не полностью. RichPost использует Rich Markdown для rich сообщений. Проверяйте конструкции в предпросмотре и тестовом сообщении Telegram.

Почему исчез один перенос строки?

Один перенос внутри абзаца становится пробелом. Используйте пустую строку для нового абзаца, два пробела в конце строки или обратную косую черту для отдельного переноса.

Что делать, если смена формата отменена?

Редактор сохраняет исходное содержимое, когда преобразование без потерь недоступно. Продолжите работу в исходном формате или упростите указанную конструкцию.
