# Синхронизация upstream при отдельном Rust runtime

**Контекст.** Upstream `nikitaCodeSave/Rich-Studio` развивает Python runtime. Форк исполняет Rust и содержит собственные публичные учётки, Telegram-вход владельца, импорт, шаблоны, редакторы исходника и виджеты.

**Решение.** История upstream вливается обычным merge. Общие файлы редактора и встроенная спецификация принимают совместимые изменения; поведение сервера переносится в Rust с содержательными тестами. Старые миграции форка сохраняют свои номера и SQL; новые колонки получают следующие свободные номера. Python-код остаётся снимком разработки форка: перенос нового поведения проверяет Rust, а линтеры Python сохраняют пригодность снимка для чтения и разработки.

Сохраняются собственные протоколы шаблонов и импорта, `rs-code-editor`, вендоренные runtime редактора/виджетов и production-образ без Python. Альтернативные реализации upstream этих возможностей не подключаются параллельно. Принятые исправления предпросмотра, сохранения полей и ограничений Bot API работают поверх существующих интерфейсов форка.

Личный rich-ответ на callback выполняется только по фактическому `callback_query_id`, без произвольного получателя. Ограниченный запрос не повторяется. Инструкция MCP встраивается из того же `SKILL.md`, который обслуживает локальный skill; отдельной копии текста нет.

После подтверждённой отправки, которую не удалось записать в БД, результат удерживается в ограниченном буфере процесса и повторяется только запись в БД. Маркер `sending` записан до сетевого запроса. При перезапуске потерянный буфер не даёт права на новую отправку: восстановление сохраняет `outcome_unknown`, а подтверждённый `message_id` остаётся в журнале, если журнал доступен.

**Почему.** Смена runtime обратно на Python убрала бы проверяемые гарантии и возможности форка. Две параллельные реализации одних UI-компонентов расходятся в формате данных и сохранении черновиков. История merge позволяет будущей синхронизации сравнивать только новые изменения upstream.

**Пределы.** Студия проверяет payload до отправки, но mock-сервер и локальный рендер не подтверждают приём настоящим Telegram. Превью формул ограничивает глубину исходника и дерева KaTeX до помещения в DOM: патологическая формула показывает ошибку с сохранённым исходником, не меняя payload публикации.
