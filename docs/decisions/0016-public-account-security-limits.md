# 0016. Отзыв прав и лимиты публичных учёток

2026-10-30. Локальный аудит воспроизвёл получение новых тем закрытой группы после удаления администратора, отправку ожидающего первого комментария без текущих прав и неограниченную запись черновиков в общий диск.

**События.** Принадлежность сохранённого поста, опроса или ссылки определяет исходный канал, но не заменяет проверку текущих прав. Перед доставкой события выполняется `getChatMember`; отказ или ошибка закрывает доставку этой учётке и не мешает остальным. Предпросмотр в собственной личке сохраняется. Первый комментарий проверяет текущие права на исходный канал и `getChat.linked_chat_id`; временная транспортная политика допускает только этот ответ, затем восстанавливается. Ранее сохранённая история остаётся доступной.

**Хранилище.** Отдельный `ACCOUNT_DATABASE_MB` ограничивает основную SQLite-базу каждой публичной учётки, включая посты, историю и фоновые записи. `max_page_count` задаётся на каждом соединении: лимит одного соединения не защищает последующие. SQLite сериализует выделение страниц между процессами. Лимит количества черновиков проверяется вместе с записью под `BEGIN IMMEDIATE`; байтовый лимит включает все сохраняемые поля. Медиа сохраняют отдельную квоту, чтобы заполненные загрузки не занимали место, выделенное базе.

**Ошибки.** `StorageFull` отделён от отказов `StudioError`: переполнение при записи результата после успешного Bot API не доказывает, что отправки не было. Идемпотентность сохраняет `uncertain`; если запись этого статуса тоже невозможна, остаётся прежний `pending`, который также запрещает повторную отправку. Ключ освобождается только для доказанного отказа до отправки.

**Пределы.** Существующая база больше уменьшенного лимита сохраняется; рост прекращается, чтение и очистка доступны. Удаление освобождает страницы для повторного использования, но не уменьшает файл автоматически. WAL и `BACKUP_KEEP` копий увеличивают физический расход сверх основной базы. Это ограничение одной учётки, а не защита от создания множества Telegram-учёток и не глобальная дисковая квота. Схема БД и рантайм-зависимости не меняются.
