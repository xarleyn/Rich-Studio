# 0024. Один Rust runtime с сохранением существующих контрактов

Дата: 2026-11-01. Основание: `RUST_REWRITE_BRIEF.md` и план `docs/superpowers/plans/2026-10-31-rust-backend-rewrite.md`.

Сервер и операторский CLI выполняются одним Rust-бинарником. Axum отвечает за HTTP, официальный rmcp — за Streamable HTTP, Grammers — за MTProto. Python остаётся эталоном поведения и локальным mock-сервером для проверок; production-образ его не содержит. Редактор, исходная Bot API спецификация, SQL-миграции и расположение данных сохраняются.

Telegram payload остаётся `serde_json::Value`: сужение до Rust-моделей полей Bot API исключило бы поддержку новых полей в день релиза. У HTTP-оболочек при этом остаются проверки типов, обязательных полей и диапазонов. Сохранённые wire-модели находятся в `src/api/compatibility.json`; Utoipa строит перечень операций и документацию из атрибутов реальных обработчиков. MCP-схемы и инструкции сохранены в `src/mcp_tools/contract.json`, а выполнение инструментов остаётся в модулях соответствующих сервисов. Тесты сверяют весь HTTP-контракт и 39 MCP-инструментов, включая annotations и metadata. Эти файлы являются исходниками контрактов; `docs/openapi.json` и `docs/reference/` пересобираются командой `make docs` из бинарника.

Интерактивные `/docs` и `/redoc` сохраняют Swagger UI и ReDoc, которые раньше подключал FastAPI. Их готовые браузерные файлы и лицензии закреплены в `app/static/vendor/api-docs/`; запуск не требует CDN, Node или новой сборки редактора. Инициализация вынесена во внешний JS, страницы сохраняют авторизацию и CSP без inline-скриптов. Swagger не отправляет контракт внешнему валидатору.

Вместо неявной области Python каждому действию передаётся `AccountContext`. Адаптеры HTTP и MCP берут его из одного авторизованного запроса. SQLite и обычные файловые операции выполняются в ограниченных рабочих задачах, сетевые запросы — асинхронно. Mutex не защищает сетевую отправку: перед ней запись устойчиво переводится в `sending` или занимает версию.

Очистка удаляет только завершённые старые ключи идемпотентности. Неопределённые `pending`/`uncertain` не истекают автоматически: удаление по возрасту разрешило бы повтор уже ушедшего поста после перезапуска или миграции. Это намеренное усиление исходной политики «не повторять, если могло уйти»; результат проверяют по каналу, а решение о новой отправке принимает человек.

При остановке прекращается новая фоновая работа, но lease сохраняется, пока завершаются HTTP-запросы. После присоединения фоновых задач lease освобождается. Неопределённые отправки и комментарии восстанавливаются в состояние, которое не разрешает автоматический повтор. Локальные проверки и Docker-приёмка не являются подтверждением выкладки на рабочий сервер.
