# 0019. Персональные API/MCP-токены из Telegram-учётки

2026-10-30. Пользователю публичного сервиса недоступен CLI владельца. Старые именные
токены открывают рабочее пространство оператора, поэтому выдавать их посетителям нельзя.
Для публичных учёток это заменяет отказ от экрана управления из ADR 0009 и закрывает
отложенный сценарий API-токенов из ADR 0014.

Создание и отзыв требуют браузерную сессию после проверенного Telegram-входа.
Права управления не выводятся из уровня publish: агент с таким токеном публикует,
но не может выпускать или продлевать себе полномочия. Персональный токен также нельзя
обменять через `/api/session` на браузерный вход. Операторский CLI остаётся прежним.

Токены хранятся в отдельной таблице корневой базы: сервер должен найти владельца
до входа в область учётки. Затем API и MCP используют прежний `accounts.scope`
и перепроверяют Telegram-права перед внешними действиями. Пользователь выбирает
read/draft/publish, срок и название; admin не выдаётся. Для изменения роли или срока
нужно создать новый токен и отозвать старый: полномочия уже выданного секрета не растут.

Секрет — 32 случайных байта, в базе только SHA-256. Он показывается в ответе создания
и открытом диалоге один раз; браузер не сохраняет его. Отзыв и срок проверяются на
каждом новом запросе. Уже принятые операции и расписание не отменяются: это отдельные
действия над постами. Лимиты создания и числа активных токенов общие для процессов;
квота проверяется атомарно. При создании история сокращается до 100 последних неактивных
токенов; вместе с 20 действующими это ограничивает список 120 записями.

OAuth не добавляли: текущая задача — подключение клиентов с HTTP Bearer и управление
выданными правами без доступа к серверу. Клиенты, поддерживающие только OAuth без
настройки заголовков, требуют отдельного сценария авторизации.
