# 0022. Личный диалог бота и отдельная очередь отчётов

Дата: 2026-10-30.

Бот принимает команды только из личного чата, где `chat.id == from.id`; текст команды и callback не выбирают учётку. Публичный пользователь может начать диалог до входа в редактор. Поэтому язык и режим уведомлений хранятся в отдельной корневой таблице `bot_contacts`, а не создают пользовательскую базу. Чтение постов выполняется в `accounts.scope` только для уже зарегистрированной учётки; в личном режиме владелец определяется положительным числовым `TG_PREVIEW_CHAT`.

Для сообщений самой студии используется узкое исключение транспортной политики: один `sendMessage` с точными параметрами текущему пользователю. Общая политика API/MCP остаётся прежней. Получатель отчёта выводится из текущего контекста при постановке в очередь и проверяется снова перед доставкой.

Отчёты записываются после фиксации результата отправки. Очередь `bot_outbox` принадлежит той же базе, что и пост. Сетевые запросы личных сообщений выполняются отдельным фоновым циклом под существующим lease. Сбой уведомлений не может пометить публикацию неудачной или повторить пост. Если диск не принимает запись очереди, публикация остаётся успешной, а потеря отчёта фиксируется в журнале.

Ключ события — ID поста и вид результата; для задержек и пропусков в него также входит назначенное время, чтобы новое расписание могло дать новый отчёт. Повторяющиеся 429 одной публикации не создают поток одинаковых сообщений. Перед доставкой задержки или пропуска проверяется актуальное состояние и время поста. Изменение режима уведомлений увеличивает ревизию подписки: накопленные сообщения прежнего режима пропускаются даже при быстром выключении и включении.

Перед отправкой отчёт атомарно помечается `attempted`. При неизвестном результате или падении процесса он не повторяется. Только `Unreachable` и 429 допускают до пяти попыток. Это осознанный выбор: возможная потеря одного уведомления предпочтительнее дубликатов после восстановления. Достоверный результат публикации хранится в `posts`, а не в факте доставки отчёта. Старые записи очереди удаляются через семь дней.

Новые HTTP/MCP-методы и зависимости не нужны. Команды и тексты RU/EN поддерживаются вручную; кнопки ведут в существующий редактор. Набор команд регистрируется через `setMyCommands` только для личных чатов. API Telegram: [команды](https://core.telegram.org/bots/api#setmycommands), [личное сообщение](https://core.telegram.org/bots/api#sendmessage).
