# Импорт сообщений Telegram

Кнопка **Импорт** сохраняет текущий черновик, читает ссылку и открывает новый черновик. Поддерживаются
`https://t.me/username/message_id` и `https://t.me/username/topic_id/message_id` (также без `https://`).
`?single` выбирает один элемент альбома, `?thread=…` задаёт тему, `?t=…` не меняет содержимое.
Ссылки на комментарии (`?comment=…`), приглашения и другие действия отклоняются. Публикации при импорте нет.

В черновике появляются визуальные блоки, HTML и Rich Markdown. Markdown использует разрешённые HTML-теги
для сложных конструкций. После импорта вкладки редактируются независимо: изменение визуального блока
не перезаписывает вручную отредактированный HTML. Источник и предупреждения остаются при сохранении.

## Подключение для полного содержимого

Получите собственные `api_id` и `api_hash` в [Telegram API Development Tools](https://my.telegram.org/apps).
Задайте в окружении сервиса (или в его существующем защищённом env-файле):

```dotenv
TG_IMPORT_API_ID=123456
TG_IMPORT_API_HASH_FILE=/run/secrets/telegram_api_hash
# При необходимости: отдельный HTTP CONNECT или SOCKS5-прокси для MTProto
TG_IMPORT_PROXY_URL=socks5://127.0.0.1:1080
```

Допускается `TG_IMPORT_API_HASH` вместо `_FILE`. Нельзя задавать оба. Эти параметры сами по себе не
авторизуют личную учётку. Без персональной сессии студия входит как свой бот через `TG_BOT_TOKEN` и
читает только публичные ссылки в пределах доступа бота. Ошибка доступа предлагает пересылку; никаких
автоматических вступлений в чаты нет. Прокси `TG_PROXY_URL` для HTTP Bot API автоматически не используется:
он может разрешать только домен Bot API, тогда как MTProto обращается к дата-центрам Telegram.

Для чтения через собственную учётку администратор запускает **интерактивно на машине сервиса** с теми же
`DATA_DIR`, API ID/hash и прокси:

```bash
python app/import_login.py                  # личное пространство владельца
python app/import_login.py --account 123456789  # публичная учётка с этим Telegram ID
```

В Docker, где рабочая папка уже `/app`, путь команды — `python import_login.py`. Телефон, код входа и пароль
2FA вводятся скрыто в терминале, не в чате с агентом. Для `--account` скрипт проверяет совпадение Telegram ID.
Сессия хранится в `DATA_DIR/accounts/<id>/telegram-import.session.txt` либо в корне `DATA_DIR` для владельца,
с режимом 0600 на POSIX; на Windows ограничьте ACL папки пользователем сервиса. Файл не входит в ZIP-экспорт
студии. Не переносите личную сессию владельца в чужую учётку. Для отключения отзовите сеанс в настройках
Telegram и удалите соответствующий файл; API ID/hash можно удалить из конфигурации после отключения.

Обычный Telegram Login в веб-интерфейсе подтверждает личность, но не создаёт MTProto-сессию.

## Если подключения нет

Студия пробует публичный веб-виджет. Его HTML не является полным API: текст/форматирование и доступные фото
импортируются, видео/аудио могут отсутствовать, о неполноте выдаётся предупреждение. Заглушка «Please open
Telegram to view this post», другой ID сообщения, приватный чат или отсутствие содержимого дают ошибку.
На 2026-10-30 обе контрольные ссылки `t.me/simple_agi/203` и `t.me/mcoadvanced/2/3450` возвращали именно
заглушку. Это не проверка полного импорта этих постов через MTProto: для неё нужно настроенное подключение.

Кнопка **Через пересылку боту** создаёт запрос на 10 минут. Откройте показанную ссылку бота, нажмите Start
и перешлите нужный пост. Принимается только следующая пересылка от вошедшего пользователя в личном чате
бота. В личном режиме отправитель определяется числовым `TG_PREVIEW_CHAT`; задайте также верный
`TG_BOT_USERNAME`. Нужны включённые `TG_UPDATES` и фоновые циклы. Запрос хранится в базе и переживает
перезапуск. Если процесс оборвался во время обработки, проверьте список черновиков перед новым импортом.

У пересылки из канала проверяются исходный канал и ID сообщения. Для группы/скрытого отправителя Telegram
может не дать исходный ID: студия явно предупреждает, что соответствие пересылки вставленной ссылке
не подтверждено. Один входящий элемент альбома создаёт один черновик; для всего альбома используйте MTProto.

## Ограничения и безопасность

- Сервер и браузер проверяют один набор примеров ссылок (`tests/import_links.json`). Сервер решает окончательно.
- Только точный хост `t.me`, HTTPS, заданная структура пути; credentials, порт, управляющие символы,
  кодирование пути, фрагменты и неизвестные параметры запрещены. Сервер сам собирает URL виджета.
- Приватные `/c/…` читаются только через собственную MTProto-сессию. Сессии и файлы выбираются из текущего
  `accounts.scope`, идентификатор учётки и путь сессии в теле запроса отсутствуют.
- Загрузка медиа проверяет адреса/редиректы и запрещает внутренние IP даже при `MEDIA_FETCH_PRIVATE=1`.
  Системный прокси остаётся доверенной границей, как у обычной загрузки медиа.
- До 30 файлов, 100 МБ суммарно, существующий `MAX_UPLOAD_MB` на файл, квота учётки, 120 секунд на операцию.
  Ошибка удаляет созданные импортом файлы. Одновременно — один импорт на учётку и четыре на процесс.
- Полный rich-пост догружается при признаке `part`; неполный ответ не сохраняется как успешный импорт.
- Защищённые и исчезающие MTProto-сообщения отклоняются. Неизвестные блоки получают видимые отметки и warnings.
  Действия чужого бота не становятся действиями бота студии; кнопки могут быть заменены отметками.
- Источник, тема, подписи и текст не задают канал публикации, расписание, закреп или callback-обработчики.

## API и проверка

`GET /api/imports/telegram` показывает доступные способы. `POST /api/imports/telegram` принимает `{url}`,
возвращает новый `draft`, `source`, `warnings`, `block_count`, `media_count`. Уровень доступа — draft.
MCP: `telegram_import_status`, `import_telegram_post`. Пересылка: `POST /api/imports/forward`, затем
`GET /api/imports/forward/{id}` в той же учётке. Полные описания генерируются в `docs/reference/`.

Проверки: `make check`; браузер — `make mock`, `make dev`, `make e2e`. Изолированная проверка интерфейса:
`E2E_ONLY=41-telegram-import make e2e`. Тесты используют подставной Telegram и структуры Telethon;
они не отправляют сообщения в настоящий Telegram и не доказывают доступность конкретного чужого поста.
