# Публичные страницы и проверка поиска

При `STUDIO_PUBLIC=on` и `STUDIO_LANDING_URL=https://example.com` главная на `/` русская, `/en/` — английская. Язык задаётся URL, без перенаправления по IP или Accept-Language. Взаимные `hreflang` включают обе версии и `x-default`; каждая версия канонична сама для себя. Английские ссылки в приложение передают `?lang=en`.

Раздел `/features/` и его перевод `/en/features/` объединяют четыре руководства: `/features/telegram-tables/`, `/features/telegram-markdown/`, `/features/scheduled-posts/`, `/features/ai-agents/`. Английские версии имеют префикс `/en`. Все 12 страниц доступны по GET и HEAD; адрес без завершающего слеша получает 308 с сохранением строки запроса. Ссылки в навигации, подвале и хлебных крошках ведут сразу на канонические URL.

Инвентарь `app/public_site.py` ограничивает публичные адреса; `app/bundled/public-site-seo.json` содержит редакционные метаданные, Schema.org и даты содержательных изменений. Файлы в `app/static/pages/` — материалы сайта, не данные учёток. `lastmod` меняется вместе с содержимым конкретной страницы, а не при запросе, запуске сервера или технической пересборке. Sitemap включает эти даты и взаимные языковые ссылки. Поисковик сам решает, когда повторить обход; `lastmod` не обещает ускоренной индексации.

`/robots.txt` разрешает обход, чтобы робот мог прочесть `noindex`. На основном домене он указывает `/sitemap.xml`: главные, раздел возможностей, руководства и их переводы. Рабочий домен, API, рендеры и локальные `/landing`, `/landing/en/` получают `X-Robots-Tag: noindex, nofollow`; HTML редактора также имеет robots-метатег. Данные учёток защищает авторизация. Неизвестный публичный адрес возвращает HTML с кодом 404 и навигацией; отсутствующий API-ресурс сохраняет машинный формат ошибки. Известные адреса приложения на публичном домене перенаправляются на рабочий домен.

## Разметка и ресурсы

Главные описаны как `Organization` и `SoftwareApplication`, руководства как `TechArticle` с `BreadcrumbList`. FAQ-разметка соответствует видимым вопросам и ответам. Здесь нет выдуманных цен, рейтингов, отзывов и гарантий. JSON-LD сериализуется безопасно; CSP разрешает его точный хэш, без разрешения произвольных inline-скриптов. Демонстрационный пост главной обёрнут в `data-nosnippet`.

Разметка помогает описать страницу, но не гарантирует расширенный результат. Google прекратил показ FAQ rich results с 7 мая 2026 года; HowTo также не следует использовать как обещание специального сниппета. Проверять синтаксис Schema.org можно отдельно от доступности поискового оформления. Официальное изменение: [журнал Google Search Central](https://developers.google.com/search/updates).

У всех публичных страниц есть Open Graph, изображение 1200×630 и `twitter:card=summary_large_image`. Публикуются настоящий `/favicon.ico`, SVG, PNG и Apple touch icon. Шрифт загружается в WOFF2; изображения страницы предлагают WebP и резервный JPEG, главный снимок получает приоритет загрузки, изображения ниже первого экрана загружаются лениво.

Версия статического ресурса вычисляется из его содержимого. Только ссылка с единственным параметром `v`, совпадающим с первыми 12 символами SHA-256 файла, получает `Cache-Control: public, max-age=31536000, immutable`; обычный URL и неверная версия получают `public, max-age=0, must-revalidate`. Это сохраняет обновляемость редактора и исключает смешивание версий его модулей. CSS и JS лендинга имеют заранее сжатые Brotli-копии: сервер выбирает их по `Accept-Encoding`, не загружая компрессор при запросе. Для остальных подходящих ответов Caddy предлагает `zstd` и `gzip`; его штатный образ не содержит собственного Brotli-энкодера. Строка `encode br` потребовала бы отдельной сборки прокси; подготовленные файлы этого не требуют. См. [Caddy encode](https://caddyserver.com/docs/caddyfile/directives/encode).

## Проверка после выкладки

Из корня репозитория:

```sh
node scripts/check-public-seo.mjs --site https://example.com --app https://app.example.com --www https://www.example.com
```

Проверка делает только GET и HEAD. Она обходит sitemap, проверяет 12 страниц, canonical, взаимные hreflang, JSON-LD, социальные метаданные, изображения, кэш, постоянные редиректы, HTML 404, favicon и закрытость приложения от индексации. `--www` проверяет уже развёрнутые DNS/TLS/редирект; локальный конфиг Caddy не является доказательством исправления работающего www-хоста. Для локального сервера можно добавить `--connect http://127.0.0.1:7424`: TCP-запросы направятся туда, а `Host` и ожидаемые canonical останутся из `--site` и `--app`. Проверку `--www` проводите отдельно через прокси.

Дополнительно откройте главную, раздел и руководства в браузере на 1400 и 390 px. Проверьте меню, переходы, доступность с клавиатуры и отсутствие горизонтального переполнения. Снимки экранов не измеряют Core Web Vitals: LCP, INP и CLS проверяют отдельно, учитывая реальные данные посетителей, если они уже доступны. Сравнивайте одинаковые URL и условия измерения.

## Индексация: действия владельца

Наличие пяти результатов `site:` из десяти старых URL не доказывает, что Google проиндексировал ровно половину сайта: этот оператор не возвращает полный список. Отсутствие verification-метатега также не доказывает отсутствие кабинета: домен мог быть подтверждён через DNS. Основание: [ограничения оператора site](https://developers.google.com/search/docs/monitor-debug/search-operators/all-search-site).

1. Откройте существующие Google Search Console и Яндекс Вебмастер для основного домена; если ресурса нет, добавьте его и подтвердите владение способом, который предлагает панель. Коды DNS/HTML берутся из кабинета владельца. Для проверки публичных страниц не нужны токены пользователей RichPost.
2. После успешной внешней проверки передайте `https://example.com/sitemap.xml`. Убедитесь, что панель смогла прочесть актуальный файл и видит 12 URL. Повторная отправка не подтверждает включение в индекс.
3. Для каждого проблемного URL проверьте последний обход, HTTP-ответ, возможность индексирования и выбранный поисковиком canonical. В GSC используйте проверку URL и отчёт об индексировании; в Яндексе — проверку страницы, диагностику и страницы в поиске. Сохраните конкретную причину: обнаружена, но не просканирована; просканирована, но не индексируется; дубль; ошибка доступа. Эти случаи требуют разных действий.
4. Запросите индексирование или переобход изменённых URL средствами панели. Не отправляйте их циклически: запрос не гарантирует срок и результат. Старый заголовок в выдаче может сохраняться после обхода, а поисковик может сформировать свой заголовок.
5. Для поддомена приложения сохраните `noindex` и возможность его прочесть. При необходимости срочного скрытия используйте инструмент временного удаления в своём GSC; постоянное исключение обеспечивает действующий `noindex`. Не закрывайте приложение в robots.txt до того, как робот увидит его.
6. Через 2–4 недели сравните статусы URL, показы, клики и запросы по русским и английским страницам. Запишите даты выкладки и повторного обхода. Для бренда полезны реальные ссылки на сервис из своего Telegram-канала, GitHub и релевантных каталогов; публикации от имени владельца выполняются отдельным действием.

Аналитика не является условием индексации. Метрику или GA4 подключают с реальным ID владельца и согласованной политикой сбора данных; в этой задаче нет выдуманных счётчиков и передачи данных посетителей сторонним сервисам. Search Console и Вебмастер позволяют начать диагностику поиска без такого счётчика.

Основания: [языковые версии Google](https://developers.google.com/search/docs/specialty/international/localized-versions), [noindex и data-nosnippet](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag), [sitemap и содержательная дата lastmod](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap). Точный статус индексации проверяется в кабинетах владельца. Изменения кода, запрос переобхода и появление страницы в поиске — разные результаты.

## Документация для агентов

Лендинг и редактор указывают `/llms.txt` через `rel=describedby`. `/agents.txt` и `/agents.json` объявляют существующие MCP и skill; `/agents.md` содержит настройку с обязательным человеческим выпуском токена, `/skills/richpost/SKILL.md` — дальнейшую работу, `/llms-full.txt` собирается из этих же источников. Все шесть документов доступны без авторизации на обоих доменах, в том числе с включённым ключом локальной студии. В sitemap остаются только HTML-страницы. После выкладки проверьте 200 и Content-Type документов, адрес MCP и ссылки на skill, сохранённые 401 для API/MCP. Наличие этих файлов не доказывает их использование поисковой системой или конкретным агентом. Решение: [0021](decisions/0021-agent-onboarding-and-install-offer.md).
