# Бот Rich Studio

В личном чате бот отвечает на команды и присылает отчёты о публикациях. Для этого нужны работающая студия, `TG_UPDATES=on` и фоновые циклы (`STUDIO_BACKGROUND=on`). При webhook используется тот же обработчик, что и при getUpdates. Меню команд регистрируется автоматически; вручную переносить его в BotFather не нужно.

| Команда | Что происходит |
|---|---|
| `/start` | Приветствие, кнопка открытия студии и включение всех отчётов при первом запуске. Повторный запуск сохраняет выбранный режим. |
| `/help` | Как подключить канал, сделать предпросмотр, опубликовать и отложить пост. |
| `/studio` | Открыть редактор. Для локального HTTP-адреса бот показывает адрес текстом. |
| `/status` | Число своих опубликованных, отложенных, отправляющихся, неудачных и пропущенных постов. |
| `/notifications` | Кнопки «Все публикации и ошибки», «Только ошибки», «Выключить». Можно написать `/notifications all`, `/notifications errors` или `/notifications off`. |
| `/stop` | Выключить отчёты; вернуть их можно через `/notifications`. |

Ответы и меню доступны на русском и английском; язык ответов берётся из языка Telegram пользователя (для остальных языков — русский). Создание поста, выбор канала и публикация остаются в редакторе/API/MCP.

В публичном режиме `/start` можно отправить до входа в студию: он сохраняет только настройки общения, без создания учётки и папки с постами. `/status` становится доступен после входа через Telegram. В личном режиме команды принимает только пользователь с положительным числовым ID из `TG_PREVIEW_CHAT`; канал или группа не могут стать получателем отчётов. В группах команды игнорируются.

Отчёт содержит название канала, первую строку поста, результат и, при успешной публикации, кнопку перехода к сообщению. Поддерживаются немедленная публикация, отправка по расписанию, отказ Telegram, задержка с безопасным повтором, пропущенное время, предупреждения о закреплении/опросе и сбой первого комментария. Ошибка после отправки оставляет пост опубликованным. Если результат неизвестен, бот пишет «пост мог уйти» и просит проверить канал; публикация автоматически не повторяется. Изменения и удаления уже опубликованных постов, ошибки валидации до начала отправки и общие серверные сбои остаются в интерфейсе и журнале.

Отправка отчётов работает через отдельную очередь SQLite в базе владельца поста, обычно с задержкой до одного цикла (10 секунд при свободной очереди). Настройки общения хранятся в корневом реестре Telegram-пользователей. После `/stop` ещё не отправленные сообщения пропускаются; включение уведомлений не создаёт отчёты о старых публикациях. Блокировка бота (403 при доставке) выключает отчёты, после разблокировки их можно включить через `/notifications all`.

Очередь переживает перезапуск. Перед сетевым вызовом запись помечается как взятая: тайм-аут, 5xx или остановка процесса не приводят к повтору потенциально доставленного отчёта. Только заведомо не отправленный отчёт (нет соединения, 429) может повториться, максимум пять попыток. Поэтому доставка не гарантируется: при падении между отметкой и отправкой отчёт может потеряться, а состояние поста остаётся во вкладке «Посты». Записи старше семи суток удаляются. Ошибка постановки отчёта в очередь логируется и не меняет результат публикации.

Импорт по ссылке `/start import_…` сохраняет прежнее назначение: бот просит переслать исходный пост, затем предлагает проверить результат импорта в студии. Неверная или устаревшая ссылка получает объяснение. Такой переход сам по себе не включает отчёты.

Проверки выполняются с `tests/mock_telegram.py`, без отправок в настоящий Telegram. Контракт команд: `tests/test_bot_dialog.py`. Решение о доставке и границах: [0022](decisions/0022-bot-dialog-notifications.md).
